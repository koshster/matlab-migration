# Statics Platform — Claude Code Guide

## Project summary
Web replacement for a MATLAB truss-homework app. Students enter answers to randomly-generated statics problems; the backend grades them server-side. An instructor dashboard lets Prof. Marko view scores, replay student problems, and export grades. Multiple students use this concurrently in a production context.

Source of truth for all decisions: `../assets/BUILD_SPEC.md`. Phases, acceptance criteria, and locked decisions live there.

## Developer split
- **Koshik** — owns `frontend/`, co-owns `packages/contract/`
- **Rushil** — owns `backend/`, co-owns `packages/contract/`
- Phase 0 (scaffold) and Phase 1 (contract freeze) are joint; all subsequent phases are parallel.

## Frontend renderer registry (critical invariant)
The truss diagram is **one of many** problem types. Every future problem type (beam, frame, etc.) must plug in with zero changes to shared components. The pattern:

```ts
// problems/registry.ts
const registry: Record<string, React.ComponentType<{ geometry: unknown }>> = {
  truss: TrussDiagram,
  // future: beam: BeamDiagram,
};
export const getRenderer = (type: string) => registry[type] ?? FallbackDiagram;
```

**If any file outside `problems/` mentions the word "truss", that is a bug.**

## Standing rules (never negotiate)
1. **Never send solutions to a student route.** Add a test whenever a student response model changes.
2. **No hardcoded problem knowledge in shared components.** `ProblemViewer`, `AnswerPanel`, routers must be fully generic.
3. **Tolerance, feedback mode, max_attempts are server-side only.** Frontend receives verdicts, never rules.
4. **Every schema change needs an Alembic migration.** No manual DDL.
5. **Contract first.** Edit `openapi.yaml` → regenerate TS types → implement both sides.
6. **Strict types everywhere.** `mypy --strict` and `tsc --noEmit` must pass. No `Any`, no `as any`.
7. **PIDs and names never appear in logs, URLs, or error messages.**
8. **No new dependency without an ADR line justifying it.**
9. **Tests before green.** A phase is not done until its acceptance criteria are automated.
10. **Ambiguities go in `docs/OPEN_QUESTIONS.md`; pick the conservative default.**

| Solver zero-row tolerance | 1e-5 | solver.py |

## RNG note (important)
MATLAB's Mersenne Twister will **not** reproduce in NumPy. Only the integer seed is stored; reproducibility is within Python only. Use `numpy.random.default_rng(seed)`.

```
make test       # pytest (backend) + vitest (frontend)
make lint       # ruff + mypy --strict + eslint + tsc --noEmit
make format     # ruff format + prettier
make migrate    # alembic upgrade head
make seed       # insert one course + one 8-problem truss assignment + one instructor account
```
